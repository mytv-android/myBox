S17

投屏与推送

投屏有三种，原版把它们混在一个列表里：推给另一台 myBox 或 TVBox，是把整部片交过去，换集和续播都在电视上完成；DLNA 只投当前这个地址；外部播放器是在本机换个播放器。myBox 分组列出，并在每组标题上说清楚区别。

rate_review对这一屏提意见
push_pin标注
  1. 搜索状态：打开面板即同时开始 DLNA 发现与局域网扫描，设备一台台出现；10 秒后停止转圈，下拉可重新搜。
  2. myBox 与 TVBox：推荐项。推过去的是整部片的信息，电视用自己的站点和解析去播，手机可以锁屏。
  3. DLNA：只投当前地址。副标题写明这台设备是否支持跳转进度，不支持的提前告知会从头播放。
  4. 其它播放器：MX、Kodi、Reex、VLC。VLC 不传请求头，加警告图标并在下方解释。
  5. 手动输入：扫不到时可以直接输入电视上显示的 IP。
  6. 正在播放：显示电视上的片名、集数与进度，进度用波浪进度条，播放中波浪在动。
  7. 方向键：圆形方向盘，中间 OK；左侧返回、主页，右侧音量。只有对方是 myBox 时才显示方向键，TVBox 只显示播放控制。
  8. 快捷操作：选集、换源、字幕直接在电视上弹出对应面板；停止投屏用红色描边按钮。
  9. 远程搜索：在手机上打字，电视上直接出搜索结果。
  10. 推送项：点播配置、直播源、弹幕源、链接；每项都说明对电视的影响。
  11. 剪贴板识别：打开推送页时检查剪贴板，是视频地址、磁力或配置地址就给一个一键推送。
  12. 收到推送：电视右上角浮出卡片，带封面和来源设备名；8 秒内不操作就自动播放（可在设置里关）。
  13. 二维码：打开本机的管理网页，兼容原版 TVBox 的手机推送方式。
  14. 开关：允许被发现、推送前询问、作为 DLNA 渲染器、本机名称。

界面协议 / 规则
DLNA 发现SSDP ssdp:all，筛 MediaRenderer:1，需要 AVTransport:1 服务；设备用 UDN 标识（§5.13.1）
DLNA 投放SetAVTransportURI → Play → 有进度时 Seek（REL_TIME），Seek 失败忽略（§5.13.2）
DLNA 请求头请求头序列化成 JSON 放进 DIDL-Lite 的 dc:description，普通渲染器会忽略（§5.13.3）
附近 TVBox扫描本机所在 C 段的 9978 端口，POST /action 返回 ok 即为一台 TVBox；不是 DLNA（§5.13.5、§11.4 第 42 条）
推送动作/action 的 do：search 搜索、api 点播配置、liveApi 直播源、danmuApi 弹幕源、push 链接（§5.13.5）；DV 版只有 search、api、push 三种（§8.2.1）
推送链接的请求头push 的 URL 后面用 | 接请求头（§8.2.1、§11.4 第 62 条）
是否送达ok 只表示设备在线，不表示动作执行成功（§11.4 第 43 条）；myBox 之间另加回执
外部播放器pl 10 MX、11 Reex（请求头为 JSON extra）、12 Kodi、14 VLC（不传请求头）（§5.8.3）
管理网页本机 HTTP 服务默认 9978，被占用时递增；二维码内容为 http://局域网IP:端口/（§8.2、§8.8）
记住的设备设置键 remote_tvbox_host（§5.8.0）
  • myBox 之间的推送在 push 之外再带上站点 key、vod_id、线路与集序号，电视收到后走自己的详情与解析，所以能换集、能续播。对方是原版 TVBox 时退回只推地址。
  • 扫描节制。C 段扫描最多 254 个并发请求，myBox 改为分批 32 个，并优先尝试上次连过的地址。
